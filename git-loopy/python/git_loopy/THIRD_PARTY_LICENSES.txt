Third-Party Licenses
====================

git-loopy redistributes no third-party material. This file names the third-party
work a git-loopy *installation* obtains, so an operator can see what will land on
their machine and under what terms before it does.

Workflow Skill catalog
----------------------

git-loopy ships no Skills. Its workflow Skill catalog is installed at setup, and
refreshed at the start of every Run, from one external source of record:

    bradcstevens/git-loopy-skills
    https://github.com/bradcstevens/git-loopy-skills

at the exact immutable revision recorded in `git_loopy/skill_source.json`, which
ships beside this file. That pin is what a released artifact resolves against, so
it can always name the revision an install came from without a source checkout
(ADR-0023, ADR-0025). The installed catalog lands in git-loopy's own config scope
(`<config-home>/git-loopy/skills/`), never inside a distribution and never inside
a consuming project.

That upstream is MIT-licensed, and its own `LICENSE` -- which git-loopy validates
byte-for-byte against the digest in the pin before installing anything -- carries
two applicable notices: the source of record's own, and the retained notice of
`mattpocock/skills` (https://github.com/mattpocock/skills), from which most of
the workflow catalog is derived. Both travel with the installed catalog, in the
`LICENSE` file at its root, which is the copy that governs the Skills on disk.

`uv run --project git-loopy/python python -m git_loopy.skill_source` acquires and
proves that revision on demand; the same validation runs on every install.

Runtime dependencies
--------------------

git-loopy's Python runtime dependencies are declared in
`git-loopy/python/pyproject.toml` and installed by the operator's package
manager, which records each package's own licence metadata. They are not
redistributed here either.
