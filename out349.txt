## #343 gave you the word, and left you the sentence

[#343](https://github.com/bradcstevens/git-loopy/issues/343) decided that an **Execution host** is *one selectable noun with two declared properties* — a **placement** and an **isolation grade** — after finding the two axes genuinely decouple:

|  | **Workspace separation only** | **Machine boundary** |
| --- | --- | --- |
| **Local placement** | today's worktree Lanes | local + a container runtime (**this ticket's** open option) |
| **Actions placement** | one job per Run | one job per issue |

The load-bearing consequence for you: **placement does not imply grade.** A remote host that runs every Lane inside one job separates them exactly as weakly as a laptop does. So "you're on the Actions host" would tell an operator nothing about isolation — which is precisely why the grade had to become its own declared property rather than folklore.

**Your second bullet is therefore answered in principle and left to you in practice.** The two grades *do* need distinct names, and the vocabulary is drafted:

> **Isolation grade**:
> What an **Execution host** declares about how strongly one **Lane contribution** is walled off from another and from the operator's machine — workspace separation alone, or a whole machine boundary. A property a host reports, never a policy git-loopy applies; a **Sandbox** is one *mechanism* for reaching a grade, not the grade itself. Placement does not imply grade: a remote host that runs every Lane in one job separates them exactly as weakly as a laptop does.

What is **still yours**: the grade *names* themselves (the draft uses descriptive phrases, not terms), whether there are exactly two or a scale, and whether the Dashboard displays it. On that last point note the ordering dependency — if it is displayed, the Rust core must read it from the Event stream, which is now [#355](https://github.com/bradcstevens/git-loopy/issues/355)'s question. Decide *whether*; #355 decides *how it is carried*.

## The rest, sharpened

- **The sentence for the docs** is still entirely yours, and #343 made it easier by giving the local host a declared value to state rather than a gap to apologize for: its grade is **workspace separation only**. That is a real guarantee, honestly named.
- **Whether local containment is worth pursuing** is now cleanly expressible: a local-container host is simply *another host* declaring a different grade. It renegotiates nothing in the seam — so this can be decided on its merits alone, and deferring it costs nothing structurally.
- **Whether ADR-0010 should be superseded.** #343 leaned on its blocked status as settled fact and did not touch its status. Still yours.
- **One constraint #343 added** that bears on the knob question: *a host authenticates itself; the orchestrator never transports credentials across the boundary.* ADR-0010's second friction (the agent needs network, keychain and `gh`) is therefore now a property the **host** must satisfy for itself, on every host. Any containment proposal has to survive that.

## Resolution

**The local Execution host promises workspace separation and nothing else — permanently, by decision rather than by defeat.** Local blast-radius containment is refused; the operator reaches a machine boundary by selecting a different host, which is what the seam is for.

The ticket opened on the premise that ADR-0010's blocking left *"an honest gap the map must name rather than paper over."* That was right, and it understated it: the gap is not unnamed, it is **mis-named in the source of record**. `CONTEXT.md:526` defines **Sandbox** in the present tense as *"the per-Iteration OS permission boundary the agent's shell commands run inside"*, and two domain rules (`:1297`, `:1329`) assert its per-Iteration and per-Lane scoping as fact, with `:1374` recording the question as a *resolved* ambiguity. The map's own Notes define `CONTEXT.md` as a glossary of **shipped reality**. So the artifact that exists to describe what ships has been documenting a mechanism that has never run once.

---

## 1. No local containment — and the reason is the grade, not the difficulty

**Decision: refused, permanently.** Three reasons, in ascending order of weight:

1. **The seam already sells containment — that is what it is for.** #350's Actions host *is* the machine boundary. A second mechanism reaching the same grade on the local host duplicates the seam's entire purpose. *"I want blast-radius containment"* is answered by selecting a host, not by setting a flag.
2. **#344 already improved the workspace half for free.** Moving Lane worktrees inside `<git-common-dir>/git-loopy/worktrees/` strengthened separation with no runtime dependency at all. That is the honest thing the local host can offer, and it is now offered.
3. **The load-bearing one: anything local can only ever deliver a *fraction* of the grade it would appear to promise.** `PROMPT.md` requires the agent to `git push` and `gh` to close its own issue, so the network-and-credential half can never be cut. This is ADR-0010's second friction — the one its own spike never got far enough to hit — and it is **structural**, not an engineering shortfall.

**The third reason is the one that makes this durable, so it is worth stating plainly: the refusal does not rest on feasibility.** A local container host is entirely buildable. It fails on what it would *deliver*: filesystem confinement wearing the name of a machine boundary — putting two materially different guarantees under one word, which is exactly the conflation #343 §2 refused when it split placement from grade.

**Consequence for the revisit trigger, and it is the counter-intuitive one: upstream shipping headless sandbox support does not reopen this.** ADR-0010 promised to revisit on exactly that event. That promise is retired here, because the event it names would satisfy a clause that was never the binding one.

### The revisit bar

Local blast-radius containment is reconsidered only when **all three** hold:

1. **It reaches the full `machine boundary` grade**, not filesystem confinement wearing that name.
2. **It costs the purely-local Run nothing when absent** — no container runtime, network or cloud account becomes a precondition (the map's standing Note).
3. **It is reachable on the headless path git-loopy actually drives**, not an interactive-only surface — the precise gap ADR-0010's spike found.

**Two of three already hold.** An optional container runtime satisfies 2 and 3 comfortably. It fails **1**, structurally, per reason 3 above. This mirrors ADR-0026's bar and #357's; unlike #357's *"zero of three"*, here the scorecard is the argument — the clauses that pass are the ones that don't matter.

---

## 2. The promise, stated plainly enough to publish

> **The local Execution host declares the isolation grade `workspace separation only`.**
>
> Each Lane contribution works in its own git worktree, so two Lanes cannot see or overwrite each other's files. **That separation is the entire guarantee.** The agent runs as you, with your credentials and your network, and nothing constrains what it writes outside its worktree — your home directory included. This is a **workspace** boundary, not a **security** boundary. If you need blast-radius containment, select an Execution host that declares `machine boundary`.

The load-bearing clause is *"a workspace boundary, not a security boundary"* — the shortest form of the distinction this ticket exists to stop papering over, and it survives being quoted out of context, which a docs sentence has to.

---

## 3. The two grades are named, and the set is closed at two

**Decision: `workspace separation only` and `machine boundary`, exactly as #343 phrased them — a closed set of two.** Not an open scale and not a number, so nobody can invent a third grade by writing a bigger integer. A third grade would have to arrive through §1's revisit bar, which is where that argument belongs.

---

## 4. Announced once per Run — not rendered per-Lane

Half this bullet was already decided elsewhere, and clearing that away is most of the work:

- **"Declared" is settled by #343** — a host declares its placement and its isolation grade. Never a #349 decision.
- **It is not the member manifest.** #348 put `execution_hosts` in `parallel_capabilities` as a list of host *identifiers* and explicitly **refused a grade** there as *"#343 §2's conflation returning."*
- **#355 owns the mechanism** and was waiting on this ticket for the requirement.

**Decision: the grade is announced once per Run.** The load-bearing reason is #343's own selection policy — **one host per Run, mixing is not shipped** — which makes the grade a **Run-level constant**. Painting it on every Lane row would render one value N times, and a per-event field would make every event pay for a value that never varies. #357 set the idiom on this map when it ruled host cost *"disclosed, not silent — a metered host is announced once"*; using the same shape keeps two disclosures of the same kind from growing two vocabularies.

**Refused: persistent Dashboard display.** It buys nothing over the announcement while costing a constant-valued element in a surface #352 was already guarding against noise in.

---

## 5. ADR-0010 is superseded in full, not left blocked

**Decision: superseded in full by the Execution host ADR — decided here, written when that ADR is written.**

`blocked` now asserts something false. The status carries an explicit revisit trigger — *"either (a) a Python SDK release that exposes a native sandbox kwarg... or (b) a CLI release that applies the local sandbox in `--headless` mode"* — and §1 just retired that promise. An ADR that says *waiting* when nobody is waiting is precisely the misleading artifact the ticket named.

**Full, not partial.** No clause survives: the mechanism is dead, the network/keychain friction was absorbed as §1's reason 3, and the *"two simultaneous runs still collide"* non-goal was already picked up by ADR-0033's **Lease**.

**Not written in this session.** #343, #350 and #352 all deferred their ADRs; #352 decided *"one new ADR supersedes ADR-0001 and ADR-0024 in full"* and wrote no file. #349 writing one alone would fragment the record for a seam whose spec does not exist yet. Repo convention pairs supersession both ways (`**Status:** superseded by` / `**Supersedes:**`) and always points at an ADR that **exists** — so the pairing lands with the Execution host ADR, not before it.

---

## 6. The term **Sandbox** is retired from the domain model

**Decision: retired.** The decisive evidence is #343's, not this ticket's: both terms it locked carry `_Avoid_: sandbox`, and **Isolation grade** explains why — *"a **Sandbox** is one mechanism for reaching a grade, not the grade itself."* The domain model had already ruled the word a conflation trap; it simply had not removed the entry embodying it. The concept survives and is carried better, because a grade is **declared per host** rather than assumed everywhere.

Per the map's sequencing convention — #343 drafted its new terms in its resolution and left the glossary alone — the edit is not made here. But the falsehood is **independent of the seam**: if the Execution host were never built, the glossary would still be lying. So it is filed as an ordinary issue rather than left hostage to implementation: [#415](https://github.com/bradcstevens/git-loopy/issues/415). ADR-0010 and ADR-0008's per-Lane sandbox-policy consequence are historical records and are **not** edited; their supersession rides with §5.

---

## 7. Two consequences worth recording precisely

**A. The `COPILOOP_SANDBOX` / `GIT_LOOPY_SANDBOX` knob is removed by never having existed.** The ticket asks whether it is kept, repurposed or removed. Checked: those identifiers appear **nowhere** in the repository except inside ADR-0010's own prose proposing a three-valued `off | on | require` control. No code, no docs, no config key. It dies with the ADR in §5 and there is nothing to migrate, deprecate or warn about — recorded so nobody later hunts for a knob to remove.

Repurposing it to *select* the grade would have been wrong regardless: #343 fixed the grade as *"a property a host reports, never a policy git-loopy applies."* An operator changes grade by selecting a different host.

**B. #293 is a homonym, not a conflict.** #293 (*"Decide whether blast-radius guards can act at git-loopy's seam"*, map #280) uses **blast radius** as a *routing* signal — *is this change big enough to reroute to the quality path*, judged from diff size and API surface. #349 uses the same phrase for an *execution* boundary — *what may this process write*. Same words, unrelated referents, different maps. Flagged explicitly because this is the collision that produces a confidently wrong cross-reference six months out.

---

## What this hands to the rest of the map

- **#355** — receives a requirement and, more usefully, a **non**-requirement. #349 asks only for a once-per-Run announcement. This does **not** overrule #343's *"Events must be stamped with the host per contribution"*: that stamping is justified by **provenance and durability**, so mixing can arrive later against an unchanged contract. #355 should decide the envelope on those grounds **alone** and must not read *"the operator must see the grade"* as forcing a per-event field.
- **#358** — inherits a sharper local picture: a Stop against a local contribution is stopping a process that runs **as the operator**, with no boundary to fall back on.
- **#351**, **#353**, **#354** — unaffected.
- **The Execution host ADR** — owes ADR-0010 a `**Supersedes:**` line (§5) and carries the published promise (§2).

Resolved by a `/grilling` + `/domain-modeling` session over six rounds. Evidence came from a full read of ADR-0010 and its spike outcome, a repository-wide trace of every `sandbox` reference (5 files, zero of them code), the ADR status/supersession conventions across all 36 ADRs, and the resolutions of #343, #344, #348, #350, #352 and #357.
