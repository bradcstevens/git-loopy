# git-loopy 0.11.0-dev.5

This development prerelease brings the committed main snapshot through
`724a820` together with the operator-approved corporate-feed compatibility and
local startup repairs. Unlike dev.4's dev.2-based maintenance branch, it includes
the newer main-line work. Unrelated in-progress working-tree changes are not
part of this Release.

## Corporate-compatible SDK and startup

- Pins `github-copilot-sdk==1.0.13` and its CLI `1.0.83`; SDK 1.0.14 was not
  available through the configured corporate feed. No other repository
  dependency version is changed.
- Revalidates all 19 observed models against that pinned harness, retaining the
  seven compatibility entries and existing configured model choices.
- Discovers global Skill metadata without opening an agent session. Load errors
  remain explicit, and closed-world Skill exposure is unchanged.
  Plugin ownership is retained from an owner-qualified canonical command when
  available. The global SDK sometimes supplies only an unqualified command;
  those rows explicitly say `plugin (name unavailable)` instead of inventing
  an owner or opening a session to recover a display label.
- Reads Unix keyboard input and cursor replies from the controlling terminal
  when stdin carries a trace or `/dev/null`, avoiding a blank Dashboard at
  launch or Attach. Real-PTY regressions cover drawing, input, and restoration.
- Retains a matching locally built helper for an explicitly source-only Release
  instead of losing it during maintenance. The tagged policy, version, and
  Event schema must agree; unavailable metadata and publication errors are not
  hidden.

## Main-line changes included

- Human-facing timestamps follow the viewing machine's timezone at each instant,
  including historical daylight-saving rules, routing provenance, and native
  Windows timezone information. Canonical Events and replay evidence stay UTC.
- Clone-scoped Run discovery and control, improved setup/startup diagnostics,
  outcome-aware routing evidence, route preparation, publication, and reuse.
  Existing configurations are not silently switched to Dynamic routing.
- Shared Run/doctor routing-readiness checks, corrected Conformance inventories,
  and release rehearsal/readback safeguards.
- Reconciled decision records for client lifetime and immutable publication;
  those records are not a substitute for outstanding behavioral acceptance.

## Source-only availability

This is a development prerelease, not a stable Promotion. It publishes committed
notes and GitHub source archives, with no compiled helper assets or package-channel
updates. Existing public tags and stable `v0.10.0` are unchanged.

Install the explicit tag through the existing uv-tool channel:

```sh
uv tool install --force "git+https://github.com/bradcstevens/git-loopy@v0.11.0-dev.5#subdirectory=git-loopy/python"
```

Corporate-managed environments must retain their configured package feed.
When using the public lockfile, export its pins without downloading artifacts,
inspect direct sources, install through the corporate index, and run without
lock synchronization. Do not bypass a missing or denied package.

Build a matching Dashboard helper from this tag:

```sh
cargo build --release --manifest-path git-loopy/tui/Cargo.toml
```

An unqualified `git-loopy upgrade` selects the stable Release; use an explicit
development version when selecting this prerelease.
