# git-loopy 0.7.0

git-loopy 0.7.0 publishes the whole of phase 2. It is the first Release since
`v0.1.0`, and it carries five milestones' worth of work that had already landed
on `main`: closed-world Skill policy, Workflow Continuation, rolling dispatch,
family-wide Dashboard insights, and the shared TUI helper with its
cross-platform distribution.

The Runner family is unchanged in shape — a Python reference Orchestrator, native
shell and PowerShell Orchestrators, and a Rust Dashboard core, all pinned against
the same Conformance fixtures.

## Why 0.7.0 and not 0.2.0

The `VERSION` file had read `0.2.0-dev.0` since the day `v0.1.0` was tagged, while
the milestones `v0.2.0` through `v0.6.0` were each finished and merged without ever
being published. Numbering this Release `0.2.0` would have named one milestone and
shipped six. The five delivered milestones are now closed against this Release, and
the version says what the tree actually contains.

## Closed-world Skill policy

A Run resolves and freezes its Skill policy before it starts, so the same Run
performed twice reads the same Skills. `git-loopy init` establishes a policy, legacy
Config is migrated before a Run begins, and a policy can be synced explicitly from
Copilot or edited with the shared plain-terminal picker. The policy is pinned in the
Wrapper contract and the Conformance suite, and the shell and PowerShell
Orchestrators fail closed on it rather than proceeding with whatever they find.

## Workflow Continuation

Continuation is a separately versioned, language-neutral contract, native in all
three Orchestrators rather than layered on one. It covers atomic completion records,
immutable Producer revisions, live frontier Reconciliation, lifecycle and ordering
projection with human guidance, and safe authorization of a fixed frontier. `/next`
is a read-only consumer of it. Planning, specification, decomposition,
implementation, review, conflict, and head transitions are published from the Skills
that own them.

## Rolling dispatch and Parallel mode

Issues are dispatched into Lanes and integrated under a gate that must be green
before a Lane's contribution merges, with the AGENTS.md feedback-loop table as that
gate's input.

## Family-wide Dashboard insights

An additive Dashboard insight contract with a shared fixture seam, and semantic
parity enforced across the family: authoritative issue activation, live Context
fill, normalized Iteration and accounting rollups, closure timing, and truthful
streaming with immutable issue binding from Python, shell, and PowerShell alike.

## The shared TUI helper

`git-loopy-tui` is a standalone Rust helper that renders the Dashboard, discovered
by any family member and supervised from the shell and PowerShell Orchestrators as
well as Python. It negotiates Event-schema capabilities rather than assuming Release
equality, and a Run whose helper stops reading falls back to raw JSONL on stdout
instead of failing.

## Compatibility

- Every public Orchestrator identity surface reports the exact shared Release
  version `0.7.0`: `git-loopy --version`, `wrapper.run.start`, and the Continuation
  capability manifest.
- Release identity is independent of compatibility identity. This distribution
  implements Wrapper contract 1.4, Event schema fixture 1.1 (compatibility
  schema 1), Continuation contract 1.2, and Continuation record format 1.
- The Runner-family Conformance gate covers the Python, shell, PowerShell, and Rust
  boundaries on every operating system each member claims, and passes on all of them
  before publication.

## Installation

- Download GitHub's automatic source archive and run the selected Orchestrator from
  the extracted tree.
- Python 3.11 or newer can install the nested Python project directly from the
  `v0.7.0` tag with `uv tool install
  "git+https://github.com/bradcstevens/git-loopy@v0.7.0#subdirectory=git-loopy/python"`.
- The clone-local shell and PowerShell installers add launchers for their native
  Orchestrators. Shell requires Bash 4+ and `jq`; PowerShell requires PowerShell 7+.

This source-only Release does not publish to PyPI, Homebrew, winget, or Scoop, and
does not include signed platform artifacts or a compiled TUI helper.

## The gate this Release had to clear

Publication is gated on Runner-family Conformance, and that gate had been red on
`main` — five of its seven jobs failing, deterministically, while every suite passed
on a maintainer's machine. Four of those failures were assertions that pinned the
environment rather than the product, and they are fixed here:

- [#386](https://github.com/bradcstevens/git-loopy/issues/386) — a Skill-scan
  exemption naming a gitignored directory no checkout has, so it exempted nothing.
- [#387](https://github.com/bradcstevens/git-loopy/issues/387) — a Rust test that
  panicked on the broken pipe left by a helper correctly reporting it had no
  controlling terminal.
- [#388](https://github.com/bradcstevens/git-loopy/issues/388) — a shell assertion
  requiring SIGPIPE at its default in the agent, which POSIX forbids any shell from
  restoring once it was ignored on entry. It now checks the invariant the live
  interface can keep: that it adds no ignore of its own.
- [#315](https://github.com/bradcstevens/git-loopy/issues/315) — the two
  Windows-only failures. The TUI installer's staging slot and the Orchestrator's
  discovery slot disagreed, because only one of them knew Windows names an
  executable by its extension; and a `gh` resolving to a `.cmd` shim was handed a
  paginated query whose `&` `cmd.exe` re-read as a command separator, truncating the
  request.

[#385](https://github.com/bradcstevens/git-loopy/issues/385) tracks the whole of it.
