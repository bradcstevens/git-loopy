# git-loopy 0.11.1

git-loopy 0.11.1 is the patch Release after
[v0.11.0](https://github.com/bradcstevens/git-loopy/releases/tag/v0.11.0). It is
cut from the complete `main` snapshot and carries everything merged since
`v0.11.0`, including the Copilot SDK upgrade that was earlier staged on `main`
as an unpublished `0.11.2`. No `0.11.2` was ever tagged or published; this
Release replaces it as the legal patch successor of `0.11.0`.

## Before you upgrade

- **Strikes are charged to each issue, and a Run never stops on them.**
  `max_nmt_strikes` (default 3) is now the number of Strikes *each issue* gets
  per Run. Every Session outcome charges its own issue one Strike and is
  retried until that limit, then skipped. A Run with nothing bindable still
  ends `all_skipped` (exit 1). The Dashboard and Python UIs show the focused
  issue's count rather than a Run-wide sum
  ([ADR-0070](../adr/0070-a-strike-is-charged-to-the-issue.md), #702).
- **The Copilot SDK pin is a prerelease.** The Python Runner now pins
  `github-copilot-sdk==1.0.17rc3` (from `1.0.14`), with its model-roster
  provenance stamped to Copilot CLI `1.0.92-3`.
- **The Wrapper contract moves from 2.17 to 2.23.**
- **Releases are source-only.** The repository's distribution policy
  (`git-loopy/conformance/release-trust.json`) now declares `source-only`.
  This Release publishes its GitHub source archives and these notes; no
  compiled `git-loopy-tui` helper or package-channel update is published with
  it (see [Distribution modes](README.md#distribution-modes)).

## What changed

### Runs and Pickup

- **A candidate awaiting a pull-request merge is passed over.** Pickup no
  longer binds an issue whose work already sits in an open closing pull
  request, in the Python Runner (#695) and in the shell (#697) and PowerShell
  (#698) Orchestrators
  ([ADR-0069](../adr/0069-a-candidate-awaiting-a-pull-request-merge-is-not-pickup-admissible.md)).
- **An Unbound Run names the pull requests it is waiting to merge** (#694).
- **Rolling dispatch retries Parallel-safe issues until N Strikes**, instead of
  giving each issue at most one Lane per Run, so Parallel mode honours the
  same per-issue budget as Sequential mode (#703, #709).
- **The user model roster is refreshed on every Run.** Each successful live
  listing replaces the advisory supported-model set, one deadline-bounded
  listing is shared by roster recording, Static validation and Dynamic
  readiness, and the committed fixture remains the offline fallback. `doctor`
  and `init` stay offline unless their selected policy already needs a listing
  (#705).

### Integration

- **Parallel Integration pushes the advanced base before closing tracker
  issues**, and a locally landed publication failure stops Recovery instead of
  closing work that never reached the remote (#418, #708).
- The PowerShell test double for `gh` reads pipeline input on Windows, so the
  Windows gates exercise the real request (#712, #713).

### Dashboard

- The Queue shows parking and admission (#682).
- The Header's parallel Declaration shows the Integration backlog (#683).
- Integration start and branch drift are emitted and shown as *integrating*
  (#684).
- Recovery attempts are emitted and shown as *recovering* with
  *recovery N/K* (#685).
- The refill turn is emitted and shown in the Header (#686).

### Skills

- The pinned Skill catalog moves to `bradcstevens/git-loopy-skills@61896034`.
  `/sync-model-roster` joins the catalog, `/next` now also chooses which Skill
  or flow fits, and the Run instructions no longer list `/loose-ends`.

### Decisions recorded

- The Planner stays outside autonomous Runs
  ([ADR-0071](../adr/0071-the-planner-stays-outside-the-run.md)).
- Independent review gates issue closure
  ([ADR-0072](../adr/0072-independent-review-gates-closure.md)) — accepted
  design.
- Language paths release and gate independently
  ([ADR-0073](../adr/0073-language-paths-release-and-gate-independently.md)) —
  accepted design.

## Publication

The candidate was rehearsed locally before its tag existed: the exact tagged
commit, its annotated tag and its source archive were proved, and every
`AGENTS.md` feedback loop ran green on that commit. The release smoke was not
run, because its credential and limits are not configured; the tag was pushed
by the operator, as `v0.11.0`'s was.
