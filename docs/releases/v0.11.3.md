# git-loopy 0.11.3

git-loopy 0.11.3 is the patch Release after
[v0.11.2](https://github.com/bradcstevens/git-loopy/releases/tag/v0.11.2).
At the operator's request it includes the complete current `main` snapshot,
not an SDK-only backport, and upgrades the Copilot SDK to stable `1.0.17`.

This is an explicitly authorized direct publication exception, as in 0.11.2.
The normal Promotion lacks its release-smoke credential and limits, and there
is no 0.11.3 milestone. The operator authorized publication without the live
release smoke, retaining candidate checks and `source-release.yml`'s
Runner-family Conformance and source-archive identity gates. No live-smoke pass
is claimed. The `1.0.0-alpha.1` development fragment remains historical; this
patch does not assert that the planned 1.0.0 acceptance criteria are met.
The operator also explicitly authorized putting `0.11.3` on `main`, lowering
its development target from `1.0.0-alpha.1`. This closes that active major line:
subsequent advances start from `0.11.3`, and reopening `1.0.0` requires a
human-applied `v1.0.0` target on a subsequently completed issue. This is an
exception to the upward-only target rule, not a change to the Runner's policy.

## Before you upgrade

- **The SDK pin is now stable.** The Python Runner pins
  `github-copilot-sdk==1.0.17`, replacing `1.0.17rc5`, and runs its pinned
  Copilot CLI `1.0.93`. A live capture through that exact CLI changed no model
  effort sets or context tiers; the roster provenance stamp moves with the SDK
  ([ADR-0019](../adr/0019-roster-derived-from-the-pinned-harness.md)).
- **Release identity is now path-specific.** Python and its Rust Dashboard
  report `0.11.3`, with Wrapper contract `2.32`. Dormant shell and PowerShell
  paths retain their declared `0.11.2` / contract `2.26` / Event schema `1`
  baselines; this Release does not advance them (#792, #839).
- **The Release remains source-only.** GitHub source archives and these notes
  are published, not compiled helpers or package-channel updates. A matching
  local Dashboard can be built from the tagged source.

## What changed

### Agent profiles and session boundaries

- The pinned catalog now includes validated Agent profiles, installed and
  repaired beside Skills (#824, #826, #838, #843).
- Execution sessions select the installed profile for the bound Task type,
  preload its Required Skills, and enforce its permitted Skill surface across
  local and remote work (#827).
- Reviewer sessions use read-only access, including permission enforcement
  for their Subagents (#828). This provides the session boundary; it does not
  claim delivery of the independent Review stage.
- Issue sessions disable harness memory and refuse cross-session history
  access (#822).
- Exact `task-type:planning` and `task-type:review` labels exclude an issue
  from execution, including explicit issue pins. Only a human can retype
  those issues; the classifier proposes execution Task types only (#823).

### Pickup, Dashboard and host behavior

- Pickup considers closing pull requests as well as dependencies, so an
  issue awaiting a PR merge is not admitted as workable (#841, #847).
- The Dashboard Header shows the Release version that started the Run (#789).
  The drill-in retains every attempt's Routed pair, Ending and recorded work,
  while Skipped issues are marked in their own Queue rows (#787).
- macOS Run work uses the utility Host yield policy so it yields to the
  operator's foreground, with an explicit opt-out. The Run discloses the
  policy, and startup diagnostics are emitted once (#816, #837).
- Run instructions bound deliberate CPU load on the operator's host (#818).

### Release assessment and tooling

- Release assessment reports unfinished and unabsorbed work, classifies
  content from a reachable baseline, and reads evidence through a dedicated
  read-only GitHub App (#782, #784, #786).
- The assessment sandbox adds explicit fault scenarios and a complete
  scenario catalog; operator documentation explains permissions and use
  (#765, #766, #840).
- Promotion preflight accepts valid configured smoke limits (#844); the
  missing credentials and limits are still required for normal Promotion.
- The Skill catalog pin advances to `7d98aa729d04cb01686793150272cf9c1094fb9a`,
  and repository agent tooling uses `GLOSSARY.md` and the two-hook chain.
