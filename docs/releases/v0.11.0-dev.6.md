# git-loopy 0.11.0-dev.6

This source-only development prerelease reconciles completed work that had
remained on feature branches with the main-line changes since
[v0.11.0-dev.5](https://github.com/bradcstevens/git-loopy/releases/tag/v0.11.0-dev.5).
It also includes the catalog repair from `15bf2aa`. It is not a stable Promotion:
the Release target remains `0.11.0`, and stable `v0.10.0` is unchanged.

## Dashboard navigation and Agent facts

- A Queue-row click opens that issue's Log; Back returns to the Dashboard.
  The current press/release identity check is retained, so a reorder, resize,
  or drag cannot open the replacement row. Wheel and keyboard scrolling share
  independent Queue, Log, and Activity positions, including pause/resume follow
  and bounded-tail retention
  ([#606](https://github.com/bradcstevens/git-loopy/issues/606)).
- Each Activity window carries its Agent's issue, Task type, Routed pair,
  Context fill, and observed Subagent count. Facts wrap at 80 columns; the
  active pair remains visible when collapsed. Concurrent Lanes retain their own
  facts, and Integration recovery does not borrow a Lane's route
  ([#605](https://github.com/bradcstevens/git-loopy/issues/605)).
- Rolling Events require the whole contribution identity and an explicitly
  null Iteration before entering the rolling attribution path. Drill-in rows
  distinguish multiple contributions on one issue. Header Parallel posture
  reports observed Run state, not the Orchestrator's capability manifest, and
  promotes degradation and serial-fallback reasons
  ([#475](https://github.com/bradcstevens/git-loopy/issues/475),
  [#476](https://github.com/bradcstevens/git-loopy/issues/476),
  [#477](https://github.com/bradcstevens/git-loopy/issues/477),
  [#478](https://github.com/bradcstevens/git-loopy/issues/478)).
- Both rolling streams are exercised through the real consumer. This includes
  the preserved branch proof and the newer main-line Event-schema adapter
  ([#479](https://github.com/bradcstevens/git-loopy/issues/479),
  [#557](https://github.com/bradcstevens/git-loopy/issues/557)).

The reconciliation preserves viewer-local time, Membership-read Queue entries,
Wind-down, additive routing fields, Run-only Consumption, and canonical billed
issue rows. It does not adopt the unfinished Session-ending or Abandonment-guard
changes from the Dashboard branch (#603 and #604).
The previously published rolling-dispatch candidate
([#474](https://github.com/bradcstevens/git-loopy/issues/474)) is now reconciled
into the release line; the parent #432 is not closed by this release.

## Routing, host disclosure, and installation

- Dynamic assessments can use explicitly mapped, comparable official
  SWE-bench Verified observations as supporting evidence. Artificial Analysis
  remains the selector-election authority; unavailable optional evidence is
  disclosed, never guessed or substituted for required evidence. Freshness
  checks do not invalidate a reusable route merely because retrieval time moved
  ([#564](https://github.com/bradcstevens/git-loopy/issues/564)).
- Run start discloses host metering and the non-triggering identity of the
  standard GitHub Actions deployment without inventing a host-compute bill
  ([#463](https://github.com/bradcstevens/git-loopy/issues/463)).
  The newer, already-published Actions host and remote-preflight implementation
  is retained instead of restoring its older feature-branch counterpart.
- Shell and PowerShell installers resolve the newest published helper no newer
  than the Runner, require the host archive and checksum, and verify the
  selected identity. Activation failure restores the previous helper and its
  resolved-Release record together. Python's newer resolver and source-only
  local-helper policy remain intact
  ([#492](https://github.com/bradcstevens/git-loopy/issues/492)).
- Native Skill-consultation Conformance now exercises the production rollup
  seam and preserves unavailable telemetry as null
  ([#555](https://github.com/bradcstevens/git-loopy/issues/555),
  [#556](https://github.com/bradcstevens/git-loopy/issues/556)).

## Catalog and migration

The Skill catalog now pins immutable revision
`20fcf612eee4d2bee2ef88fdee4cba7ae51b4392`, with 43 Skills including `/release`.
Its README inventory and offline snapshot agree. `writing-great-skills` is
retired in favor of `writing-for-agents`; review saved policies and custom
prompts that still name it. Required Skills and saved operator policies are
not rewritten. `/release`, `/loose-ends`, and `/model-fit` remain user-invoked
operations, not autonomous Iteration follow-ups.

Main-line routing preparation, retry/reuse, explicit setup and upgrade
migration, and bounded publication/Consumption proofs are included. Existing
Static authority is preserved; this is not final Dynamic-default activation
(#567). Planning documents with `PRD:` or `Spec:` titles are not executable
work. Python's landed Lease activation and native pure identity seams are
included, but native Lease transport and the remaining #390 obligations are
not claimed complete. Publication inputs are bound to the committed
distribution promise; the unfinished stable-publication and downloadable-helper
work (#590 and #592) is not waived by this prerelease.

## Source-only availability

This Release publishes authored notes and GitHub source archives only.
It publishes no compiled helper assets or package-channel updates, moves no
existing public tag, and preserves SDK `1.0.13` / CLI `1.0.83` and other dependency pins.

Select the explicit prerelease through the existing uv-tool channel:

```sh
uv tool install --force "git+https://github.com/bradcstevens/git-loopy@v0.11.0-dev.6#subdirectory=git-loopy/python"
```

Keep corporate package feeds configured. For a lockfile with public artifact
URLs, export pinned requirements without downloading, inspect direct sources,
install through the corporate index, and run without synchronization. A denied
or missing package is a blocker, not permission to use another registry.

Build a matching Dashboard from this tag to use all newly reconciled features:

```sh
cargo build --release --manifest-path git-loopy/tui/Cargo.toml
```

An unqualified `git-loopy upgrade` selects the stable Release, not this
development prerelease. Publishing dev.6 does not update an operator's installed
Runner or stop an active Run.
