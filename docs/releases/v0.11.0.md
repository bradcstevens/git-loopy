# git-loopy 0.11.0

git-loopy 0.11.0 is the first stable Release since
[v0.10.0](https://github.com/bradcstevens/git-loopy/releases/tag/v0.10.0). It is
cut from the complete `main` snapshot. Everything listed here was built since
`v0.10.0`, including work that earlier shipped only in development
prereleases, whose tags have been retired.

## Before you upgrade

- **A local Run needs a Route policy.** A local Run refuses before any Agent
  work when saved Config selects neither a Static nor a Dynamic **Route policy**.
  A local Run with no Config at all also refuses. `git-loopy doctor` reports the
  same blocker. Record the choice once, per project or with `--global`:

  ```sh
  git-loopy update --project --routing keep      # route_policy = "static"
  git-loopy update --project --routing migrate   # route_policy = "dynamic"
  ```

  **Keep** leaves your saved routes and run-wide default in charge. **Migrate**
  keeps every `[routing]` row you wrote and uses Dynamic routing only for work
  those rows don't cover. It needs `GIT_LOOPY_ARTIFICIAL_ANALYSIS_API_KEY`
  (kept outside Config) and a verified `[route_associations]` table.
  `--route-policy` or `GIT_LOOPY_ROUTE_POLICY` sets a policy for one invocation
  only (#567).
- **A bare Run is always parallel.** The Python distribution's mode switches
  are gone, and the contract rows were re-scoped to match (#458).
- **The Run outlives its terminal.** A Python Run now detaches from the terminal
  that started it, and the Dashboard attaches to it as a client (#459). Use
  `git-loopy runs`, `git-loopy attach <run-id>`, and `git-loopy stop <run-id>`
  to find, observe, and stop a Run.
- **Route labels changed shape.** Publication writes separate `model_id:`,
  `model_context:` and `model_effort:` labels instead of the truncated
  `git-loopy-route:` label. `git-loopy route-labels migrate --apply` converts
  existing issues. Stop or upgrade every Runner that publishes Route labels
  first (#614, #615, #616).
- **Release-target labels replace `semver:*`.** A closed issue's `vX.Y.Z`
  label now names its Release target. Prereleases follow Semantic Versioning
  `alpha`/`beta`/`rc` stages, and closing a `vX.Y.Z` milestone promotes the
  line (ADR-0066).

## Runs and the Dashboard

- **Detached Runs with client attachment.** The Run keeps going when its
  terminal closes. Any number of Dashboard clients can attach to it and detach
  again without owning or ending it (#459, #586).
- **Acknowledged Stop by Run identity.** `git-loopy stop <run-id>` asks a live
  Run for a two-stage Stop (drain, then cancel) and waits for the
  acknowledgement. Any attached client can send the same Stop through the
  control channel (#461, #585).
- **Windows attachment.** On Windows, the helper follows a Run's trace and
  control lock the same way it does on Unix. It uses a non-blocking shared lock
  on the first byte of the control artifact, the same range the Runner holds
  (#592).
- **Navigation and Agent facts.** Clicking a Queue row opens that issue's Log.
  Queue, Log, and Activity scroll independently. Each Activity window shows
  its Agent's issue, Task type, Routed pair, Context fill, and Subagent count
  (#605, #606).
- **Header posture.** Parallel posture reflects the Run's observed state and
  surfaces degradation and serial-fallback reasons. Wind-down and the Execution
  host are shown (#464, #475–#479, #557).
- **Rolling-dispatch closure.** The `wrapper.pipeline.quiescent` Event is
  retired, and the rolling stream gets its missing closures (#679). Parallel
  Runs prove `contribution_events: true` by what they emit (#680). The
  Lane-work boundary is now an Event, and Active time ends there (#681).
- **Clear empty-Pool outcomes.** A Run that finds no workable issues tells the
  operator why, instead of quietly closing the Dashboard (#642). An
  `all_blocked` Rolling Run records the blockers it was waiting on, in
  selection order (#643).
- **Local time.** Human-facing timestamps use the viewer's local timezone at
  each instant, including historical daylight-saving rules and native Windows
  timezone data. Canonical Events and replay evidence stay in UTC (#596).
- **Terminal robustness.** On Unix, keyboard input and cursor replies are read
  from the controlling terminal when stdin carries a trace or `/dev/null`. This
  avoids a blank Dashboard at launch or Attach. The live-attach PTY test no
  longer flakes in CI (#640).

## Pickup, Pins and readiness

- **Awaiting merge.** An issue whose closing pull request is still open is not
  Pickup-admissible. It is a wait, not a failure, and it resumes when that pull
  request merges or closes (#692).
- **Readiness verdicts name their reason.** Each verdict names its own refusal
  reason and unbound-Pool class (#693).
- **Pin lifetime is the same everywhere.** A Pin is spent at the first Pickup
  that reads it, across the whole Runner family (#644). Pinning a plain
  `ready-for-agent` issue works now that Parallel mode is unconditional
  (#430). A pre-bind Lane failure no longer passes over a parallel-safe Pin,
  and a Lease-remote outage no longer costs a unit per retry (#645).
- **Planning documents stay out of the Pool.** `PRD:`/`Spec:` issues and
  `wayfinder:map` issues are excluded as `planning_document` in all three
  Orchestrators, and pinning one refuses. `git-loopy labels --apply` removes a
  stray `ready-for-agent` from them (#627, #628, #630, #635).

## Routing

- **Dynamic routing** is the declared default for unpinned new work in
  Python-local Runs. It chooses a route from live Artificial Analysis evidence,
  with optional, explicitly mapped SWE-bench Verified observations as
  supporting evidence. Validated routing results are reused while still fresh
  (#561, #563, #564, #565, #567).
- **Static routes reach the work that actually runs.** Detached workers
  preserve the selected `route_policy`. A Static route on GitHub Actions
  proceeds only when that host's own model listing, and the local one, both
  accept it (#560, #567).
- Run start discloses host metering and the GitHub Actions deployment identity
  without inventing a host-compute bill (#463). The Execution host decision
  record, the ADR-0043 amendment, and the glossary terms have landed (#465).
- Routing in the shell and PowerShell Orchestrators is still deferred.

## Setup and installation

- **Wizard-first setup.** The fullscreen setup wizard is the only interactive
  renderer, and Textual is a base dependency. For non-terminal setup, use
  `git-loopy init --yes` (#501, #508, #510).
- **A safer `uninstall`.** It shows its removal plan, asks for confirmation,
  preserves repository contents and Run logs by default, and refuses live or
  unprovably dead Lane work. Repository scope is removed only with `--all`.
  The operator reference now separates `update`, `upgrade` and `uninstall`
  (#520, #529, #531).
- **Discoverable commands.** Root `--help` groups commands by category,
  `git-loopy help` is an alias, and `git-loopy commands --json` is a
  schema-versioned inventory for shell completions (#530).
- **Clone-scoped Runs.** `git-loopy runs` lists this clone's Runs, with
  liveness reported correctly for the platform (#584). Setup cancellation and
  blocked-startup diagnostics are more precise (#583).
- **Helper resolution.** `update` and the shell/PowerShell installers resolve
  the newest published Dashboard helper at or below the installed Runner. They
  verify its checksum, identity, and Event-schema compatibility, and restore
  the previous helper if activation fails (#492).

## Release engineering

- Semantic Versioning prerelease stages and `vX.Y.Z` Release-target labels
  (ADR-0066).
- Every stable candidate is rehearsed as an exact snapshot before its tag
  exists (#587, ADR-0059). A bounded real-host release smoke proves the

## Availability and installation

This Release publishes its committed notes and GitHub's source archives.
The repository declares `artifact-bearing` distribution, so the Dashboard
helper is built for all seven targets. However, a stable Release attaches
helper archives only when every stable trust gate passes: Developer ID signing,
macOS notarization, Windows publisher identity, and build attestation. The
publishing environment does not hold those credentials yet. The gate refuses
the helper rather than downgrading it, so **no helper archives are attached
to 0.11.0**, and the Homebrew, winget and Scoop channels are not updated.

Install or move the Python Runner (Python 3.11+):

```sh
git-loopy upgrade --to 0.11.0
# or
uv tool install --force "git+https://github.com/bradcstevens/git-loopy@v0.11.0#subdirectory=git-loopy/python"
```

Build a matching Dashboard helper from the tag, and put `git-loopy-tui` on
`PATH` or in `.git-loopy/bin/`:

```sh
cargo build --release --manifest-path git-loopy/tui/Cargo.toml
```

Keep corporate package feeds configured. A missing or denied package blocks
installation; do not fetch it from another registry instead.
