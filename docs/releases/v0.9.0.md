# git-loopy 0.9.0

git-loopy 0.9.0 is a **stable** Release: the `v0.9.0` milestone is met, every
one of its fourteen issues is closed, and its content is on `main`. It
supersedes the `0.9.0-dev.0` prerelease, which published the floor this Release
stands on and said so at the time.

One thing was owed, and it is what shipped. An operator configured a `[routing]`
table mapping each **Task type** to the `(model, effort)` pair that suits it,
ran `git-loopy`, and **nothing changed** — no error, no warning, and no surface
that would say so. Every issue was worked on the run-wide pair, which for a
quality-posture default is a slow, expensive, high-reasoning model, so an
overnight Run completed fewer issues than the same wall clock on a routed one.
0.9.0 makes the table take effect, makes the Run say what it did, and gives a
stalled issue somewhere to go.

The Runner family is unchanged in shape — a Python reference Orchestrator,
native shell and PowerShell Orchestrators, and a Rust Dashboard core, all pinned
against the same Conformance fixtures.

## The table takes effect

`git-loopy` with no flags is serial, so the default invocation was exactly the
one invocation where routing could not take effect. `_pick_active_issue`
resolved a **Routed pair** from the issue's own labels, refused a mislabelled
candidate on the strength of it — and then threw the pair away and substituted
the run-wide one.

ADR-0027 had scoped routing to Parallel mode on a fact rather than a judgement:
the serial path folded the whole **Pool** into one prompt on one pair, so there
was no per-issue thing to route. ADR-0032 then gave a serial **Iteration** a
**Pickup** of its own and #394 made that Pickup bind exactly one **Active
issue**, which killed the premise two slices before anything killed the rule.
What survived was a predicate discarding a decision the runner had already made.
**ADR-0037** records the reversal: `routing_in_force` answers true at every
parallelism a Run can have, and the pair a Pickup resolves is the pair its
session runs on.

## It says what it did

**Every Pickup publishes the pair it resolved, and why.** `wrapper.pickup.bound`
is *extended* rather than joined by a second Event — two records on the wire at
the same instant, with the same key and the same cardinality, would make every
consumer rejoin them to answer one question. The record now owns its wire form,
so the projection is pinned once beside the resolver instead of being open-coded
at the serial site and again at the **Lane** site. The **Routing source** is a
closed vocabulary, so an operator can tell a deliberate route from a fallback,
and a fallback from an unknown key, a label conflict, or a run-wide override.
**ADR-0039** carries the decision.

**Run start reads back the table it parsed.** `[routing]` has no validator and
can never have one: the key is the operator's vocabulary and the pair is the
vendor's, and nothing outside the Run can say whether a well-formed table is the
one the operator meant. So a half-filled table parsed silently, a route no issue
exercised was never resolved and therefore never gated at all, and the
**Escalation rung** was first gate-checked at a stalled issue's *next* Pickup —
the one moment the Run is already going badly. The readback names the **Default
pair**, the keys actually parsed, the keys left unconfigured, and the gate
verdict on every configured pair, at all three drive paths. It is the only
validation available anywhere, which is why it exists.

**The Dashboard shows the pair each issue is priced at.** Routing became
resolvable, effective, visible on stdout and readable back at Run start while
the surface an operator actually watches still showed one run-wide model and
called it "model" — so every issue in the **Queue** looked like it cost the same
thing, and an escalation changed what an Iteration spent while changing nothing
anyone could see. Three surfaces now read the one record: the header's run-wide
pair is relabelled the **Default pair** it has been since routing took effect,
the Queue gains a `Route` column, and the **Iteration breakdown** gains the same
column on the contribution. Both reducers implement it — the Rust Dashboard core
and the Python Textual one — pinned against the same fixture so they cannot
answer differently.

## The corpus stops needing a human

Routing shipped, was corrected and locked in the prerelease, and still routed
nothing: **zero** issues carried a `task-type:` label, so every unit of work
fell back to the Default pair whatever the table said. The open backlog was
hand-labelled at admission — 24 issues, one key each from the closed seven-key
taxonomy — which is the producer the contract names and a permanent chore, since
the 25th issue admitted the next morning would fall back again.

So the classifier that had shipped in three tested halves, with no production
call site anywhere, acquired one. An unlabelled candidate is classified at
Pickup, through the one seam a serial Iteration and a Lane already share, so
both modes classify identically. A tracker write that fails still routes the
Iteration: the label is how the answer is *remembered*, not how it is used.

## A stalled issue gets one harder pair, once — and then the Run moves on

An Iteration that made no progress was worked once, on one pair, and the Run had
no way to try it differently or to stop trying. The same issue came back at the
same pair every Iteration until the **Strike** ceiling ended the Run, so a Run
with nine workable issues and one that could not be finished spent its whole
budget on the tenth.

**Escalation** is a per-Run in-memory ledger answering one question — which
issues this Run owes a harder pair — asked at the single Pickup seam both modes
resolve through, because the evidence is about the *issue* and not about the
mode that collected it. It is immediate, so the retry happens while the issue's
context is still the most recent work, and it is **strike-free**, so trying
harder is not punished by the mechanism that aborts the Run.

**Skipping** is what happens after. `attempt_lifecycle` is a monotonic per-issue
state — `fresh` → `retrying` → `skipped` — fed from the one session-ending seam
a serial Iteration and a Lane already share. It is a *pickup* filter and not a
Pool filter: the Pool stays whole, so closure and collection are unchanged, and
only the candidate list narrows. **ADR-0040** records the bound.

## A Strike counts an issue given up on, not an Iteration

The Strike counted unproductive Iterations, consecutive, reset by progress. That
was the right ceiling for a Run with no memory of which issue had already
failed, because an Iteration was the only unit it could count. Once the Run had
that memory the ceiling went on counting the other thing — so a Run with nine
workable issues and one that cannot be finished ended after three wasted
Iterations with eight issues left to try, and a Run whose every candidate was
already skipped charged a strike for an Iteration that never opened a session
and called it `stuck`.

An Iteration is not something a Run can give up on; it is something a Run
*spends*. `max_strikes` now reads as **how many issues this Run may abandon
before it stops** — exactly one Strike per issue, charged at the transition into
`skipped`. Progress resets nothing, because the ledger it counts is monotonic
and one issue's advance must not un-abandon another; time-to-abort roughly
doubles, which is recorded rather than discovered later. An Iteration whose
Pickup can bind nothing from a non-empty Pool ends the Run under the new
`all_skipped` reason with exit 1 — not `empty_pool`, whose exit 0 would tell a
supervising script the Run succeeded, and not `stuck`, which is the ceiling
being spent and is reachable here with the ceiling untouched. **ADR-0041**
records it.

The shell and PowerShell Orchestrators have no Pickup, so they have no lifecycle
to charge from and keep the original accounting. The now-forked fixture cases
are retained under a per-case distribution selector rather than deleted, and
both adapters assert their retained count is non-zero, so a selector typo fails
loudly instead of running nothing.

## The last two session endings get their detectors

Two of the five **Session outcome** endings were unreachable. Content filtering
arrives on fields the harness already sends and the mapper already discarded,
and the no-more-tasks sentinel was a parameter two Wrapper functions accepted,
discarded unread, and no production call site ever passed. So an Iteration spent
being refused, and an Agent reporting its issue unworkable, both reached the Run
as "silently produced nothing" — which is precisely the distinction escalation
and skipping now depend on.

Both fields are kept additively by omission, like the billing figures beside
them: a harness that says nothing adds no key, so silence reads as unknown
rather than as a call affirmatively cleared.

## A Run that can never fill a Lane says so

A Parallel-mode Run over an issue source that implements no Lane work degrades
entirely to the serial path, and the degrade is correct — the fallback works the
same issues to the same outcome and strands nothing. What it never did was say
so, so `--parallel 4` produced a Run byte-identical to a serial one underneath a
banner claiming four Lanes. That is exactly the collapse the capability
declarations exist to prevent, arriving through a *source* fact instead of a
*distribution* one.

`wrapper.parallel.degraded` is a distinct literal rather than a reason on an
existing record, because a latch is repeated and transient where a degrade is
once and permanent, and it is emitted at the branch rather than inside the
degraded path, because a fact settled before any round would otherwise read as
something the Run kept re-deciding. The renderer stops inferring the degrade
from a null `effective_lane_limit` — right about the Python Orchestrator's own
stream by coincidence, a fabrication about anyone else's.

## What 0.9.0 owed, and what it delivered

The `v0.9.0` milestone carried fourteen issues and closes with all fourteen
closed. #401, #402, and #403 were published by the `0.9.0-dev.0` prerelease.
This Release publishes the remaining ten — #404 through #413 — and closes #400,
the specification all thirteen implement.

A milestone records delivery and a tag records publication. Here they agree,
which is the ordinary case and worth saying only because the previous two
Releases were each an instance of them coming apart.

## Compatibility

- Every public Orchestrator identity surface reports the exact shared Release
  version `0.9.0`: `git-loopy --version`, `wrapper.run.start`, and the
  Continuation capability manifest.
- Release identity is independent of compatibility identity. This distribution
  implements Wrapper contract 1.28 — 1.19 at `0.9.0-dev.0`, 1.16 at 0.8.0 —
  Event schema fixture 1.1 (compatibility schema 1), Continuation contract 1.3
  accepting 1.0 through 1.3, and Continuation record format 1.
- The Wrapper contract moved nine revisions since the prerelease and the Event
  schema moved none, because every new literal is additive and reserved within
  compatibility schema 1. A consumer pinned to `event_schema_version` 1.1 skips
  an unmodelled Event type exactly as it always has.
- Per-issue routing, escalation, the attempt lifecycle, and measured routing are
  declared **Python-only** in the Wrapper contract. The shell and PowerShell
  Orchestrators run the loop, declare the new Event literals for vocabulary
  parity, emit none of them, and keep Iteration-counted Strikes because they
  have no Pickup to charge from.
- `max_strikes` changes meaning. It counted consecutive unproductive Iterations
  and now counts issues abandoned, so an existing value permits roughly twice
  the wall clock it used to before a Run aborts.
- The Runner-family Conformance gate covers the Python, shell, PowerShell, and
  Rust boundaries on every operating system each member claims, and passes on
  all of them before publication.

## Installation

- Download GitHub's automatic source archive for the `v0.9.0` tag and run the
  selected Orchestrator from the extracted tree.
- Python 3.11 or newer can install the nested Python project directly from the
  tag with `uv tool install
  "git+https://github.com/bradcstevens/git-loopy@v0.9.0#subdirectory=git-loopy/python"`.
- The clone-local shell and PowerShell installers add launchers for their native
  Orchestrators. Shell requires Bash 4+ and `jq`; PowerShell requires PowerShell
  7+.

This is the source-only publication path. It does not publish to PyPI, Homebrew,
winget, or Scoop, and it attaches no signed platform artifacts and no compiled
TUI helper. Those pipelines are gated on what each artifact can prove about
itself, and the credentials that would let a stable artifact prove it are not
provisioned — so nothing incomplete is published rather than something partial
being published and called signed.
