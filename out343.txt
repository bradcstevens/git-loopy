**Resolved.** An **Execution host** is where one **Lane contribution** executes. Six decisions, in the order they had to be taken.

---

## 1. What crosses the boundary: a contribution, not a command

The ticket proposed a capability surface of *"provision a workspace at a revision; run a command and return its exit status and output; stream Events; hold credentials; be torn down."* That is a **thin** seam — a remote-controllable machine the orchestrator drives step by step — and it is **ruled out**, for two independent reasons:

- **It has no implementation on the map's one concrete remote host.** #346 established there is no live log streaming and no tail API for a running Actions job. There is also no *inbound* channel: you cannot send "now run this command" into a job already running. A job is handed its inputs at dispatch, runs to completion, and reports back. A synchronous per-call round trip has nowhere to land.
- **The thing that most needs to move cannot move as a command.** The agent session is an in-process SDK object whose file-editing tools act on the orchestrator's own filesystem (`session.py:598-735`); one `CopilotClient` hosts N Lane sessions, pinned only by `working_directory` (`session.py:576`). Relocating the *workspace* while keeping the *session* local relocates nothing.

**Decision: the unit that crosses is a Lane contribution, and its return value is a branch** — a thing git already knows how to move between computers. This is the shape an Actions job already has, and the shape the shell Orchestrator's `copilot --yolo -p "$prompt"` subprocess already has (`lib/orchestrator.sh:1676`). The family already contained both execution models; this picks the one that has two implementations.

## 2. One selectable noun, two declared properties

The ticket asked whether this is one concept or two (a *placement* and an *isolation grade*). The axes genuinely decouple, and #350's open question is what proves it:

|  | **Workspace separation only** | **Machine boundary** |
| --- | --- | --- |
| **Local placement** | today's worktree Lanes | local + a container runtime (#349's open option) |
| **Actions placement** | one job per Run — Lanes as worktrees inside it | one job per issue — reference §7's "complete computer boundary" |

All four cells are meaningful. *Remote does not imply isolated*: an Actions job hosting every Lane separates them exactly as weakly as a laptop does — for $0.72 instead of $5.76 (#346).

**Decision: one selectable thing, two declared properties.** You select a **host**; the host **declares** its placement and its **isolation grade**. Selection stays one-dimensional; the honesty #349 needs stays expressible. Rejected: *one opaque concept* (the grade becomes folklore and #349 has nothing to declare) and *two independently selectable dimensions* (a 2-D surface with combinations nobody implements).

## 3. Bound per Lane contribution — and the orchestrator's location is not a host

**A conflation had to be broken first.** #350 offers *one workflow per Run* vs *one workflow per issue*. The first is **not an Execution host**: git-loopy runs inside an Actions job with worktree Lanes on that runner's disk, exactly as it runs on a laptop. Nothing crosses a seam — it is invoking the CLI on a different computer, which already works today (the **Minimal Skill policy** exists precisely to keep *"a first CI Run"* usable). Only *one job per issue* separates the orchestrator from the work.

**Where the orchestrator process runs and where a Lane's work runs are different facts.** The seam owes nothing to the first.

**Decision: the binding granularity is the Lane contribution.** A per-Run binding cannot express what §2 just established — "Actions, one job per Run" and "Actions, one job per issue" would be the *same host* despite different isolation grades. To express them under a per-Run binding you end up saying "the Run's host is Actions, and also each Lane's host is Actions", which is per-Lane in disguise.

**Selection policy: one host per Run. Mixing is not shipped.** Mixed placement means two credential regimes live at once (`gh` is Run-scoped and keychain-backed locally per `gh.py:13-14`; `GITHUB_TOKEN` inside Actions per #345) and makes #351's "which credential publishes" conditional on provenance. Nothing in the destination requires it. Splitting mechanism from policy keeps mixing available later — as the eventual answer to #354's *"burst to Actions, keep the laptop busy"* — against an **unchanged** seam.

Consequences: Integration must not assume every branch it gates came from the same place, and **Events must be stamped with the host per contribution** (see "New ticket" below).

## 4. An outcome contract, with exactly one named exception

**What the orchestrator hands over** — one contribution request: the issue reference, its rendered prompt, the base revision, the resolved model and reasoning pair, and the **Effective Skill policy**.

Note the last: the orchestrator sends the *policy* (which Skill names are enabled); the host acquires its own **installed catalog** (the files). That is existing vocabulary doing exactly the work it was defined for, and it settles the *responsibility* half of the map's "Skill catalog acquisition inside an ephemeral host" fog — that patch was foggy only because the seam had not been drawn.

**What the host owes back** — a **durable branch with no uncommitted or untracked work, reachable by the orchestrator from its own repository**, or a terminal failure; the contribution's **Events**; and its declared **placement** and **isolation grade**.

**What the host does not owe — three of which are not obvious:**

1. **It does not run the feedback loops.** The runner never runs them in Lane work; the *agent* runs them inside its own session, and only Integration re-gates (`gate.py:5-7`). "Run the gate" was never a Lane-side capability to relocate.
2. **It does not return a verdict.** Per ADR-0020 a contribution resets **Strike** only after green publication *and* verified closure, both Integration's. The host returns a branch, never a judgement about it. The Strike machine stays wholly orchestrator-side and needs nothing from the host.
3. **It does not receive credentials.** #345 established Actions self-authenticates from the platform (`GITHUB_TOKEN`, no stored secret); locally it is the operator's keychain.

> **Rule of the seam: a host authenticates itself. The orchestrator never transports credentials across the boundary.** A host that cannot authenticate itself is not usable.

**Decision: an outcome contract** — the host owes *properties of a returned branch*, not a sequence of steps. A procedural contract would re-import every local assumption into the contract and make any host that works differently non-conformant for no observable reason.

**The single named exception is Checkpoint.** The host must leave the branch clean and the orchestrator cannot reach in to do it remotely. A **Checkpoint** commit is not private: it carries `CHECKPOINT_TRAILER_KEY` and is close-keyword-free, and downstream code reads that trailer (`wrapper.py:184-239`). So: *any commit a host authors to clean the tree must be a Checkpoint in the contract's sense.* One exception, stated with its reason — because the artifact is contract-visible, and nothing else the host does is.

## 5. The seam covers Lane contributions only — and local is a genuine implementation

**Local is not a degenerate special case.** The one apparent divergence is *durability*: locally the returned branch is already a ref; remotely the machine is about to be destroyed. State the obligation as **"the branch is reachable by the orchestrator from its own repository"** and it is one obligation with two implementations — existing already satisfies it, pushing satisfies it. That is a seam, not a bag of exceptions.

**Three things in a Run are not Lane contributions**, and none of them binds to a host:

- a **serial Iteration**, which per ADR-0020 takes *"exclusive use of the base worktree"*;
- **Integration**, which stages in a private worktree beside the base;
- the entire shell and PowerShell loop — those Orchestrators have no Lane concept at all, and already *refuse* a Lane cap > 1 through `git_loopy_assert_parallel_supported` (`lib/orchestrator.sh:994-1020`).

**Decision: the Execution host binds Lane contributions only.** Serial work is in-place work on the orchestrator's own checkout, wherever that is.

What this buys and what it costs:

- **Buys:** shell and PowerShell declare no Execution host support and stay **fully conformant** — they never had a contribution to place, so #348 gets a clean answer rather than a carve-out. And "the orchestrator's own checkout is not a host, it is just where the orchestrator is" keeps §3's separation honest.
- **Costs, accepted:** a Run whose Lanes burst to Actions still does its serial-required work *and its Integration* on the orchestrator's machine. #351 asks whether serial fallback survives a remote topology — this answers **yes, unconditionally**, at the price that the orchestrator's machine is never idle and must always be able to do real work.

## 6. What the abstraction refuses to promise

The ticket named two. Four more surfaced, one of which is a live trap.

1. **Not a scheduler.** A host may *declare* capacity as a fact (#346: 20 / 40 / 60 / 500 concurrent jobs by plan). It never decides how much to use. **Effective Lane limit**, **Pressure signals** and refill stay in the Run. #354 gets an input, not an authority.
2. **Not a policy engine.** It receives *resolved* values — the model and reasoning pair, the **Effective Skill policy** — and resolves nothing itself.
3. **Never silently retries a contribution.** ⚠️ GitHub Actions offers native job retry and re-run-failed-jobs. A host that retries invisibly makes the Run's iteration cap, AI-credit accounting and ADR-0020's `K <= 3` bound *lie about what happened*. A failure is **returned**; the Run decides what follows.
4. **Never writes to the tracker.** No `gh issue close`, no comments, no labels. Closure is Integration's, after verified green publication. A `Closes #N` in a commit message is a commit artifact travelling with the branch, not a tracker write.
5. **Is not the Run's observability endpoint.** It emits into the Run's Event stream; the always-on JSONL log (`sinks.py:12-15`) stays the single durable record. Without this, #352 becomes "attach to N hosts" instead of "attach to a Run".
6. **Does not mint identity.** `run_id` and the contribution's identity are handed to it. It names nothing.

## Glossary — two new terms

`CONTEXT.md` describes shipped reality, so these are recorded here and enter the glossary when the code implements them (the sequencing convention ADR-0024 used for **Terminal owner**).

> **Execution host**:
> Where one **Lane contribution** executes. It receives a contribution request — the issue, its rendered prompt, the base revision, the resolved model and reasoning pair, and the **Effective Skill policy** — and returns a durable branch the orchestrator can reach from its own repository, plus that contribution's **Events**. It authenticates itself; credentials never cross into it. It declares a **placement** and an **isolation grade**, and decides nothing else — **Rolling dispatch**, **Integration**, the **Strike** machine and issue closure never cross it. A serial **Iteration** has no Execution host: it is in-place work on the orchestrator's own checkout.
> _Avoid_: sandbox, container, VM, worker, workspace, Lane (a scheduler slot).

> **Isolation grade**:
> What an **Execution host** declares about how strongly one **Lane contribution** is walled off from another and from the operator's machine — workspace separation alone, or a whole machine boundary. A property a host reports, never a policy git-loopy applies; a **Sandbox** is one *mechanism* for reaching a grade, not the grade itself. Placement does not imply grade: a remote host that runs every Lane in one job separates them exactly as weakly as a laptop does.
> _Avoid_: sandbox, security level, isolation mode, trust level.

---

## What this hands to the rest of the map

- **#350** — its first option is not a host at all, so it is no longer choosing between two host shapes. Also inherits the Skill-catalog answer and refusal 3.
- **#351** — narrowed twice: publication is *always* the orchestrator's push (one `GITHUB_TOKEN` site, not one per Lane), and serial fallback survives unconditionally.
- **#349** — **Isolation grade** is now defined vocabulary; the local host's declared grade is "workspace separation only".
- **#348** — shell and PowerShell declare no host support *cleanly*, and the declaration precedent already exists in `GIT_LOOPY_PARALLEL_CAPABILITIES_JSON`.
- **#352** — refusal 5 keeps attach a property of the Run, not of a host.
- **#354** — a host declares capacity; the Run decides utilization.

Resolved by a `/grilling` + `/domain-modeling` session over six rounds. Evidence came from a full trace of the Run/host boundary surface in the Python, shell and PowerShell Orchestrators.
